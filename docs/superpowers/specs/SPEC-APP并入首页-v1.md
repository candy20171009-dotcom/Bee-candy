# BeeFintech 官网改版 SPEC（APP 页面并入首页）

## 1. 变更背景

当前官网导航包含独立 `APP` 页面。为简化用户路径、提升首页信息完整度与转化效率，决定取消 `APP` 独立页面，并将其能力内容合并到首页统一展示。

本次变更以“减少跳转、强化首页闭环叙事、提高预约转化”为目标。

## 2. 变更目标

1. 去掉顶部导航中的 `APP` 菜单项。
2. 取消独立 `APP` 页面作为主入口。
3. 将 `APP` 页面核心能力模块整合进首页。
4. 保持现有 `安全 / 分红查询 / 预约演示` 页面可用。
5. 不影响现有 API、表单提交和分红查询功能闭环。
6. 分红查询按 `2022年分紅達成率.xlsx` 口径提供查询与展示能力。

## 3. 范围定义

### 3.1 本期包含

1. 首页信息架构调整（新增“APP + CRM 协同能力”模块）。
2. 顶部导航调整（移除 `APP`）。
3. 旧 `APP` 页面内容迁移到首页对应区块。
4. 用户从首页可直接理解移动端能力与角色价值（顾问/团队长/运营）。

### 3.2 本期不包含

1. 安全页、分红页、预约页的业务逻辑重构。
2. 新增后端接口或数据库结构变更。
3. 新的权限系统或账号体系。

### 3.3 锁定区域（本期禁止改动）

首页首屏 Hero 区（用户截图区域）保持不变，不做任何视觉与文案调整，包括：

1. `LIFEBEE APP + CRM` 标识样式
2. 主标题“快人一步 / 保險數碼化”
3. 副标题正文文案
4. 两个主按钮文案与样式（预约产品演示、分红查询）
5. 首屏统计文案（175+ 经纪团队采用...）

## 5. 首页新增/合并模块设计

新增模块建议命名：`APP + CRM 协同能力`

### 5.1 模块目标

在首页直接说明 BeeFintech 移动协同能力，减少用户跳转成本，并强化“从资讯到介绍费”的闭环认知。

### 5.2 模块内容（来自原 APP 页）

1. 能力卡片：
- 产品库
- 产品对比
- 保费试算
- 客户管理
- 消息提醒
- 名片分享

2. 角色价值说明：
- 顾问：快速响应咨询、移动跟进
- 团队长：掌握节点、优化协作
- 运营：维护进度、保障流程完整

3. 行动按钮：
- `预约产品演示`（跳转 `/demo`）

### 5.3 在首页中的推荐位置

放在“六步业务闭环”之后、“2025 核心升级能力”之前或之后（二选一）：

1. 方案 A（推荐）：闭环 -> APP+CRM 协同 -> 2025 升级
2. 方案 B：闭环 -> 2025 升级 -> APP+CRM 协同

推荐理由：方案 A 更有叙事连续性，先说明“怎么协同”，再强调“升级能力”。

### 5.4 首页排版模块坐标（用于沟通改版）

为便于后续快速沟通“改哪里、怎么改”，首页统一采用模块编号。后续需求评审与改动说明，均建议按以下编号描述。

#### 模块编号（由上到下）

1. `H1` 首屏左侧 Hero 文案区  
   含：`LIFEBEE APP + CRM` 标识、主标题、副标题、双按钮、175+ 说明  
   备注：属于锁定区域，本期禁止改动

2. `H2` 首屏右侧看板区  
   含：核心闭环卡片、同步状态卡、AI 建议书卡、私有部署卡

3. `M1` 六步业务闭环区  
   含：6 张流程卡（资讯/产品库/投保/新单/保单/介绍费）

4. `M2` APP + CRM 协同能力区（本次并入重点）  
   含：6 张能力卡（产品库、产品对比、保费试算、客户管理、消息提醒、名片分享）  
   含：角色价值 3 卡（顾问/团队长/运营）  
   含：CTA（预约产品演示）

5. `M3` 2025 核心升级能力区  
   含：4 张升级卡（AI 保单同步、Eform 无纸化投保、合规资料库、邀约神器）

6. `M4` 三大关键功能区  
   含：3 张功能卡（预约演示转化、分红达成率查询、AI 能力可视化）

7. `M5` AI 展示区  
   含：AI Chatbot 与 AI 计划书步骤展示（Step 1/2/3）

8. `M6` 底部转化 CTA 区  
   含：预约 Demo、进入查询工具

#### 每个模块的可调维度

1. 文案：标题、副标题、说明、按钮文案
2. 结构：卡片数量、列数、模块先后顺序
3. 视觉：颜色、边框、阴影、圆角、留白、背景
4. 交互：按钮跳转、锚点、hover、轻动效
5. 数据：静态文案与数据源映射关系

#### 标准提需求格式（建议）

1. `模块编号`：如 `M2`
2. `改动类型`：文案 / 结构 / 视觉 / 交互 / 数据
3. `当前问题`：一句话说明
4. `目标效果`：希望改成什么
5. `限制条件`：哪些不能动（例如保留 H1 不改）

示例：

`改 M2（结构）：6 张能力卡改成 3x2 布局，角色价值卡保留在能力卡下方，按钮文案不改。`

## 9. 风险与应对

### 风险 1：首页内容变长导致首屏后信息密度过高

应对：采用卡片分组、折叠文案、清晰标题层级，保持扫描效率。

### 风险 2：历史 `/app` 外链失效

应对：设置 301 重定向并观察一段时间后再移除。

### 风险 3：模块并入后视觉节奏混乱

应对：统一卡片样式、留白与按钮体系，按“闭环 -> 协同 -> 升级 -> 转化”顺序排布。
